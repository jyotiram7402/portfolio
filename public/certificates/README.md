# Certificate scans

Drop a file here and add one entry to `data/certifications.ts`. That is the whole job — the
homepage strip, the library page, the subject filter, the search index and the viewer all read
from that array.

## Naming

Name the file after the entry's `slug`:

```
public/certificates/udemy-spring-microservices.webp
public/certificates/udemy-devops-aws-java.webp
public/certificates/gfg-java-backend-developer.webp
```

Slugs are lowercase, hyphenated, and start with the issuer — `udemy-`, `anthropic-`,
`coursera-`. That keeps the directory sorted by issuer without any extra metadata.

## Images vs PDFs

Both are supported, and they do different jobs:

| Field   | What it is                          | Used for                            |
| ------- | ----------------------------------- | ----------------------------------- |
| `image` | A **displayable** image             | The card and the viewer             |
| `file`  | The **original** PDF                | The "Open the PDF" button           |

If you only have a PDF, set `file` and leave `image` undefined — the card renders the generated
visual and still offers the PDF. **Better:** export a page of the PDF as an image too and set
both. A card that shows the actual certificate is worth far more than one that makes a recruiter
click through to a PDF viewer.

Exporting a PDF page to an image, if you need to: open it, zoom to fit, screenshot the
certificate area, crop to the border.

## Format and size

- **4:3 landscape.** That is what the card and viewer reserve, and it is what the issuers
  actually export — a Udemy certificate is 1600×1190. Other ratios still work: the image is
  letterboxed, never cropped.
- **1600px wide is plenty.** Nothing displays it larger than about 700px.
- **`.jpg` or `.webp`** are both fine. `next/image` re-encodes to AVIF/WebP at request time,
  so the committed format only affects repository size, not what a visitor downloads.
- Keep each file **under ~400 KB**.

## Extracting the image from a Udemy PDF

A Udemy certificate PDF is a single embedded JPEG — the PDF is just a wrapper. So the image
can be copied straight out of it with no re-encoding and no quality loss, rather than
screenshotted. Search the file for the JPEG start marker (`FF D8 FF`) and write from there to
the last end marker (`FF D9`); that byte range *is* a valid `.jpg`.

The six Udemy scans in this directory were produced exactly that way.

Anthropic's certificates are different — real text PDFs generated by ReportLab, with no image
inside. Those ship as `file` and render the generated cover, which is fine: they carry a live
`verify.skilljar.com` URL, and a working verification link is a stronger artefact than a scan.

## Only set `image` when the file exists

`next/image` renders a broken image for a missing path and cannot fall back, so `image` stays
undefined until the asset is committed. Undefined is the safe default, not a gap.

## Why the images are letterboxed, not cropped

`CertificateCover` uses `object-contain`. A certificate is a fixed-aspect document with its
border, logo and signature near the edges — `object-cover` would crop exactly the parts a reader
is checking. That is the opposite of the rule for a project screenshot, where cropping is fine.

## What the generated visual is for

Every entry without an `image` gets one: a ruled double frame, the issuer's accent as a corner
wash, a seal built from the certificate's initials, and the issuer name in mono. It is designed
to read as a document rather than as a missing image, so a grid mixing scans and generated
covers looks intentional.

It currently carries the two Anthropic certificates and the GeeksforGeeks one.

## Redacting before you upload

These files are public. Certificates sometimes carry more than you want indexed — a personal
email, a postal address, a full date of birth. Check before committing, and paint over anything
you would not put on the page in plain text. The credential ID is fine and belongs on the page;
it is how a recruiter verifies the certificate.
