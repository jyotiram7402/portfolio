# Live-site audit — 2026-11-06

Backlog from a full UI/UX, responsive and load-time audit of
https://portfolio-one-smoky-84.vercel.app (commit `142a8da`). Nothing here has been fixed yet.
Workflow: one branch per group below, verified on the Vercel preview or live URL before merging.
Delete an item, or mark it done, in the same commit that fixes it.

**Method.** Playwright (Chromium) against production: 10 routes × 5 widths (320, 390, 768, 1024,
1440), dark and light themes, real keyboard and touch input, raw HTML and response headers, and
cold-cache loads on Lighthouse's mobile profile (Slow 4G: 562.5 ms RTT, 1.44 Mbps down; 4× CPU
slowdown). Timings include Southco's proxy. See "Re-running the measurements" at the end.

Priority: **P0** visibly broken or blocks fast load · **P1** significant · **P2** moderate ·
**P3** polish.

## P0

### B1 — Hero name renders at 16px instead of display size
- Evidence: computed `font-size: 16px` on `#hero-heading` at every width. The shipped `<h1>` has
  no `text-display` class, so the role line under the name is bigger than the name.
- Root cause: `cn()` is `twMerge(clsx(...))` (`lib/utils.ts`). tailwind-merge doesn't know the
  custom `display` font size, classifies `text-display` as a text colour, and drops it because
  `text-foreground` follows it (`features/hero/components/hero-section.tsx:72`).
- Fix: `extendTailwindMerge` registering `display` as a font size; also register the other custom
  utilities that can collide the same way (`text-gradient*`, `bg-grid`, `bg-dots`,
  `border-gradient`).

### P1 — Page content is invisible until JavaScript hydrates (every route)
- Evidence: every route ships `<main><div style="opacity:0;transform:translateY(12px)">`. With
  JavaScript disabled, or a failed chunk, pages stay blank (header and footer only). `/recruiters`
  on the phone profile: first paint 2.0 s, content visible 5.9 s. The hero name, portrait and
  buttons are also server-rendered at `opacity:0`.
- Side effect: Chrome's LCP is misleading — 2.3 s on mobile, measured on the *navbar* text,
  because everything else is hidden; 2.85 s on desktop.
- Root cause: `components/animation/page-transition.tsx` (`motion.div`, `initial="hidden"`,
  server-rendered) and the hero's `TextReveal` / `Reveal` wrappers.
- Fix: render visible on the server (animate only on client-side navigations, or CSS entrances
  that don't start from opacity 0 above the fold), plus a no-JS safety net.

### P2 — The loading screen holds the homepage
- Evidence: phone profile — loading screen until 8.3 s, name visible at 9.1 s. Desktop without
  throttling — 3.1 s. It plays again in every new tab (the flag lives in sessionStorage).
- Root cause: `components/common/preloader.tsx` waits for `document.readyState === "complete"`,
  then a 900 ms minimum, then an exit animation (`PRELOADER` in `config/animations.ts`).
- Fix: remove it (recommended), or make it CSS-only and dismiss at first paint. Also touches
  `components/layout/site-shell.tsx`.

## P1

### C2 — GitHub Actions CI fails on every push
- Evidence (GitHub API, 2026-11-13): the last five runs on `main` all failed at "Set up Node".
- Root cause: no lockfile is committed; `actions/setup-node` with `cache: npm` and the `npm ci`
  step both require `package-lock.json`. Typecheck, lint and build therefore never run in CI —
  only Vercel's build catches errors.
- Fix: run `npm install` once on a machine that allows it and commit `package-lock.json`. If no
  such machine exists, switch `.github/workflows/ci.yml` to `npm install` and drop `cache: npm`.

### P3 — Too much JavaScript on first load
- Evidence: 421–443 KB compressed JS in 35–43 files; TBT 1,656 ms on the phone profile (longest
  task 392 ms), 286 ms on desktop; 106 `"use client"` files.
- Contributors: framer-motion 45 KB (imported by 43 files, mostly for reveals); site content shipped
  as JS (certifications + assistant knowledge + FAQ ≈ 20 KB, projects 11 KB, blog data ≈ 10 KB,
  partly in the shared layout chunk); Radix Tooltip 18 KB; zod reaching the client through
  `config/site.ts` → `lib/env.ts`.
- Fix ideas: `LazyMotion` + `m` components, CSS for simple reveals, load the search index and
  assistant data on demand, keep env validation server-side.

### A1 — Focus is lost when the menu, chat or search closes
- Evidence: open with the keyboard, press Escape → focus lands on `<body>` for the mobile menu,
  the chat drawer and the command palette (WCAG 2.4.3).
- Root cause: the triggers are plain buttons with `onClick`. Radix Dialog's close handler focuses
  its internal trigger ref, which only `Dialog.Trigger` sets.
- Fix: use `Dialog.Trigger` (the Drawer needs a `trigger` prop) or pass `onCloseAutoFocus`.
- Files: `components/ui/drawer.tsx`, `components/layout/mobile-nav.tsx`,
  `components/common/floating-actions.tsx`, `components/common/command-palette.tsx`,
  `components/layout/search-trigger.tsx`.

### M1 — iPhone zooms the page when a text field is focused
- Evidence: 11 inputs at 14px — contact form ×7, homepage chat box, newsletter email, blog search,
  search palette. iOS Safari zooms inputs under 16px (documented behaviour; no real iPhone used).
- Fix: 16px on small screens (e.g. `text-base md:text-sm`) in the input primitives.

### S1 — robots.txt blocks the social preview image
- Evidence: `og:image` and `twitter:image` point to `/opengraph-image`; robots.txt disallows
  `/opengraph-image` and `/twitter-image`. X and LinkedIn honour robots.txt when fetching preview
  images, so shared links can appear without one.
- Fix: remove both entries from `seoConfig.excludedPaths` in `config/seo.ts` (`app/robots.ts`
  derives its list from there).

### U1 — Homepage is 52 phone screens long (owner's decision)
- Evidence: 44,091 px at 390×844 (78.7 screens at 320). About 9.2 + Experience 9.8 screens, so
  the first project appears after about 23 screens. Roadmap 4.1, Achievements 3.6, GitHub 2.8,
  Speaking 2.5, Resources 1.9. Homepage HTML: 611 KB decoded (235 KB RSC payload), 3,515 elements.
- Options: condensed About/Experience on mobile with "read more"; move Roadmap / Achievements /
  Resources / Speaking to their own pages.

  (search 44px, chat 56px, back-to-top 44px); a homepage scroll sweep at 390px found 54 distinct

## Re-running the measurements

- Use the Playwright MCP's `browser_run_code_unsafe` and create contexts with
  `page.context().browser().newContext({ ignoreHTTPSErrors: true, viewport, isMobile, hasTouch })`
  — needed behind Southco's TLS inspection.
- Throttle with a CDP session: `Network.emulateNetworkConditions` (latency 562.5, download
  `1.6 * 1024 * 1024 * 0.9 / 8`, upload `750 * 1024 * 0.9 / 8`) and
  `Emulation.setCPUThrottlingRate({ rate: 4 })`; clear the cache with
  `Network.setCacheDisabled({ cacheDisabled: true })`.
- Skip the preloader in layout checks by setting `sessionStorage['portfolio:v1:preloader-seen'] =
  '1'` in an init script; switch theme with `localStorage['portfolio:theme'] = 'light'`.
- Each `browser_run_code_unsafe` call starts a fresh sandbox (globals are lost) and times out after
  roughly a minute: batch three or four page loads per call, and store reusable helpers on the
  persistent `page` object (e.g. `page.__A = { ... }`).
